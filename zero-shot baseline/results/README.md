以后每次实验新建日期与 run ID 对应的报告，包含：

- 完成/停止状态、开始结束时间及停止原因。
- 完整 dataset ID、MAT 哈希、初始分群来源及评测标注来源。
- 模型与 effort、输出上限、提示词哈希、controller/观测/评测器版本及源码哈希、随机设置。
- **Stepwise 栏**：逐通道列专家动作来源/哈希、操作前状态验证、固定样本总数、已运行/失败/未运行数、准确率、各类 precision/recall/F1 和混淆矩阵；说明 source/target 是否由评测器给定，不能把给定对象的动作判断称为自主目标选择。没有可靠 KEEP/NOT_MERGE 标签的类别不虚构成绩。
- **Rollout 栏**：模型动作独立推进状态，不按专家轨迹纠偏；下列终态指标只用于完整结束的通道。
- 每通道终态 Precision、Recall、F1、群数、保留 spikes、专家 spikes 误删及噪声保留情况；附不做 curation 的参照。
- 两项分别列调用次数、tokens、耗时、标准价估算与保守预算台账，再列合计；共享本次独立 $50 总上限，不是各 $50。未知费用另列，不冒充服务商账单。
- 典型失败案例与证据，区分已观察事实与原因假设。
- 未完成通道不填完整终态成绩；保留失败与停止记录。当前 many-to-one 评分对过度拆分处罚有限，报告需说明。
- 同配置先逐通道报告，再声明汇总方式；不得混合旧 skill 实验形成单一均值。
- 结论同时回答“在专家状态下是否选同样的动作”和“自主执行最后得到什么分群”。动作高分不能替代终态结果；不同轨迹的第 N 步不能直接配对。一项完成、另一项未完成时分开标状态，不能宣布两项 baseline 都完成。

详细本地材料引用 `../runs/<run_id>/`；此目录仅放汇总文档，不放原始数据、图像或响应。
