## 1. 设置

模型、harness、题目和计分方式都与基线相同：Tengyang `f1ca871`，skill_v4 起点，严格专家重放，每一步无论模型怎么答都执行专家动作，计分看 gate 之后的最终动作。

学习方式：重放过程中，模型每答错一次就触发一次优化。提议者是同一个 Qwen（关 thinking），它能看到当前规则和 gate（gate 只读）、出错这一步的图像和测量值、模型的原始回答，以及专家动作和理由（推断出的 KEEP 和 CH20 没有理由），最多提出 3 条规则改动。候选改动要依次通过三层筛选：静态检查（长度、占位文本、录音特定内容、能否加载）；修复检查（用候选 skill 重答出错的那一步，最终动作必须等于专家动作）；回归检查（K=3，重答之前最近 3 道已标注的题，原来答对的不能答错）。通过后，从下一题开始使用新 skill。

链：CH31 从 skill_v4 学起，CH3 从 CH31 学完的 skill 学起，CH30 从 CH3 学完的 skill 学起。CH20 不参与学习，分别用学完 1、2、3 个 dataset 的 skill 各测一次。另外补测了学完 1 个之后的 CH3 和 CH30，以及学完 2 个之后的 CH30。测试时不学习。

运行事故：第一次链式运行时，脚本读取上一环 skill 的命令丢了引号，导致所有环节和测试都用了原始 skill_v4。CH31 那一环本来就该从 skill_v4 开始，所以保留；CH3、CH30 和全部测试都在 `_rerun` 目录中重跑过，每次运行的 manifest 都核对过 skill 版本和 sha256。误跑的 6 次测试实际上是 skill_v4 的重复测量，下面拿来估计运行间的波动。

## 4. 解读

第一，学到的东西主要是"更倾向删"。各通道的 DISCARD 一致率普遍上升（例如 CH30 学习中 37/41，skill_v4 重复测量为 32 到 34/41；CH20 学完 1 个后 14/22，基线 11/22），SPLIT 也有提升。推断 KEEP 却没有改善，甚至变差：CH20 从 2/12 降到 0/12。由于严格重放的题目大多是专家要动的 cluster，"永远 DISCARD"本身就有不低的一致率，所以偏向删除会抬高总分，但这不等于判断变好。

第二，迁移收益小，也不随学习量增加。CH20 学完 1 个后是 +3 题（40 对 37），刚好在噪声边缘；学完 2 个、3 个后回落到 38 和 37。CH30 用只学了 CH31 的 skill 测出 80，比学完 CH3 后的 76 和它自己学习过程中的 74 都高。规则越加越多、越来越长，但没有带来更好的泛化，后面几环的改动可能在相互抵消，或者在过拟合各自 dataset 的个例。

第三，dataset 内的收益只有 CH31 明显超出噪声（49 对 43）。CH3 是 77 对 73/74，略超噪声；CH30 学习过程中是 74，与基线持平或略低。

第四，筛选器很严格。大多数候选在修复检查这一步就失败了（模型在同一题上换了规则仍然答错）。回归检查一次都没有拦下候选，说明 K=3 的回归约束基本没有发挥作用，被接受的改动对后续题目的副作用要到后面的题目上才看得出来。提议者有 4 次尝试去改 gate，都被拦下了。

## 5. 局限

每个配置只跑了一次，而噪声大约是 ±3 题，所以几题的差异不能当作结论。推断 KEEP 题数很少（CH20 只有 12 题）。CH20 的专家动作没有理由文字，CH3 和 CH31 来自同一个录音块。严格重放会把状态强制拉回专家路径，所以这里的一致率不等于自主运行时的分群质量。

## 6. 可考虑的下一步

把 KEEP 和 DISCARD 的权衡单独拿出来看：学习后的 skill 是否在系统性地把真神经元删掉。回归检查可以改为抽样更远的历史题，或者增大 K，或者专门包含 KEEP 题。提议者可以允许删除或合并规则，避免规则只增不减。每个配置最好重复 2 到 3 次，以便和噪声区分开。
