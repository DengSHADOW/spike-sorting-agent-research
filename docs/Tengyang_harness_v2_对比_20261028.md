## 核心变化

| 项目 | 原基线 | harness-v2 |
|---|---|---|
| controller | 逐个请求、逐个推进的交错式 `CurationControllerV2` | 新增 `RoundsController`，同轮冻结状态、集中回答后再执行；旧类保留 |
| 配对 | top-k 已 KEEP 群，按请求顺序遇到 MERGE 即执行 | 按轮收集配对；按相关性处理答案，同一簇每轮最多参加一次改变状态的配对操作；冲突答案作废并记录 |
| 配对补查 | 无独立 final sweep | 默认进行一次未问配对的收尾扫描；不保证覆盖全部配对 |
| 并发 | 请求串行 | 图像准备串行、模型回答可并行；相同回答下保持确定性执行，不证明真实模型并行生成完全一致 |
| 观测 | raw_member_v1 | 新增 observation-v2：波形密度、分层抽样轨迹、ISI/ACG、幅值时间变化、CCG、拆分预览及污染估计 |
| 请求图片 | 单簇 4，簇对 3 | 可拆单簇 5、叶子单簇 4、簇对 3 |
| 指令组织 | minimal prompt | 冻结 contract + 独立版本化 skill |
| 模型输出 | action + rationale | 图像观察分类和描述 + action + rationale |
| 运行入口 | 无完整新版本地 rollout 入口 | 新增本地模型单通道 rollout 与 smoke 脚本；首轮不支持续跑 |
| 停止态 | 不作为完整终态评分 | 新入口允许单列 stopped_state 分数，与完成态分开 |

新版观测不是把全部原始轨迹逐条画出：单簇波形图使用全部成员的密度统计，加最多 500 条分层抽样曲线；不要与网页的全波形展示混为一谈。

新增 seed skill 共 17 条规则（single 10 条、pair 7 条），标为未验证种子，来源包含开发数据专家理由及外部经验。它已有领域先验，不能称作不含专家知识的 minimal zero-shot。比较固定 agent 和反馈更新 agent 时应使用同一个种子起点。

## 对我们的反馈优化项目的意义

1. **更自然的接入点**：`SkillDecider` 支持 `skill_path`，记录 skill 版本与哈希。优化器可以产出新的 skill 文件，下一次运行显式加载；当前不自动热更新。
2. **更细的反馈定位**：输出分别记录波形、ACG、幅值时间、树/拆分预览等观察，可帮助区分看图错误与动作判断错误。这些仍是模型自述，不能自动当作真实因果解释。
3. **运行基础更完整**：本地 vLLM 单通道运行器已存在，不必从零写整个入口；托管 API 的认证、模型名、参数、计费和响应校验仍需适配。
4. **controller 仍未学习**：选簇、top-k、配对排序、冲突处理和 final sweep 都是程序规则。新版没有提供新增的人类调度监督数据。
5. **自动反馈闭环仍缺失**：文档将反馈导入与 optimizer 明确推迟；本次代码未新增这些模块。可替换的 skill 是优化接口，不是已完成的自优化。

上游方案只开放 skill 更新，冻结 controller/观测等层；用户正在讨论的“开放 controller 策略学习”是独立扩展，需要另定可修改接口和评估方法。
